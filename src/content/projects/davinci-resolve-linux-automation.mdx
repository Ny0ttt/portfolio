## The Problem

DaVinci Resolve's scripting API only exists in the paid Studio edition. On the free edition — and on Linux — turning a multi-hour stream into an edit means placing every caption, cut and layout by hand.

## The Approach

Go around the API instead of through it. Resolve already **imports** timelines, so the pipeline writes the formats Resolve reads natively and leaves the creative pass to a human. Nothing is rendered or burned in — you import the files and keep editing normally.

```
VOD link + time range
   │
   ├─ transcribe  (whisper.cpp, word-level)
   ├─ align       (DTW word starts + VAD-trimmed ends)
   ├─ review      (optional by-ear fixes)
   ├─ score       (loudness / emotion spikes → highlight candidates)
   │
   ▼
timeline_normal.fcpxml · timeline_short.fcpxml · captions.srt
```

## Features

- **Word-level transcription** with whisper.cpp, then alignment so captions land on the word
- **Highlight scoring** from loudness and emotion spikes to propose a rough cut
- **Two layouts** — a normal timeline and a stacked vertical Short
- **Animated captions** written as Resolve's own `.drt` timeline format, each word chunk popping in
- **Preflight** that names any missing tool or path and refuses before a run starts
- **CI smoke suite** proving every module imports, every CLI responds and the docs agree with the code

## Stack

- **Language**: Python 3.12 (numpy, scipy, librosa for audio signals)
- **Transcription**: whisper.cpp, built from source
- **Media**: ffmpeg / ffprobe
- **Output**: FCPXML, OpenTimelineIO, Resolve `.drt`, SRT

## Key Challenges

- **Reverse engineering Resolve's formats.** With no API, every output had to match what Resolve actually accepts on import — including its native `.drt` timeline format, built from exported templates.
- **Caption timing that feels right.** Raw whisper timestamps drift; word starts are aligned with DTW and ends trimmed with voice-activity detection.
- **Honest testing.** The public CI suite proves consistency, not output quality — quality is validated against real footage before each release, and the README says so.
